2026-11-10 KST. 사용자 선택: **온라인 방식도 검토 — 정확도 우선**, 이어서 **OpenAI API 사용 가능** 확인. 공식 문서 검토 및 합성 음성 API 비교 2회차 완료. 이후 debug 전용 Mac 중계 경로를 앱에 연결·설치했다. 실제 사용자 온라인 발화는 대기 중이다.

## 실행 준비 상태

- `scripts/compare-online-stt.py` 준비. 기본 실행은 파일 검증만 하고 키를 읽거나 네트워크에 접속하지 않는다. `--execute`가 있어야 OpenAI로 4회 이내 요청한다. 실패 시 재시도 없이 중단하고 HTTP 상태만 기록한다.
- 비교 대상은 `docs/online-stt-fixtures.json`의 SHA-256으로 고정한 기존 합성 WAV 4개(총 4.8934375초). 정답 금액·항목은 로컬 결과에만 남기고 요청에는 중립 파일명 `audio.wav`와 한국어 힌트만 넣는다.
- 키는 프로세스 환경변수 또는 Git 제외 `.env.local`의 `OPENAI_API_KEY`에서 읽는다. 로컬 파일을 접근 권한 600으로 준비했고 사용자 저장 확인 후 키 인증/API 요청 성공을 확인했다. 키 값은 출력하지 않았다. shell로 파일을 실행하지 않는다.
- `python3 -m unittest discover -s scripts -p 'test_compare_online_stt.py'`로 multipart, 파일 변조/형식, 응답 형식/재시도 없음, dry-run 무접속, redirect 차단을 검사한다. 실제 서비스의 계정 권한·품질 확인과 구분한다.
- 실행 명령: `python3 scripts/compare-online-stt.py --execute`. 결과는 Git 제외 `artifacts/phase3/asr-diagnostic/online-<UTC>.json`. 전사 원문을 얻어도 제품 파서와 실제 사람 발화 검사는 별도로 남는다.

## 먼저 확인할 것

- 사용 가능한 API 계정·결제/크레딧·서비스 선택. 키 값은 채팅에 받거나 APK에 포함하지 않는다.
- 사람이 녹음한 음성을 보낼 때 서비스와 전송 범위를 명시한다. 현재까지 사용자 실제 음성은 저장·전송하지 않았다. 사용자가 키 저장 완료를 알린 뒤 기존 합성 WAV 4개를 OpenAI로 두 회차 전송했다(총 8요청).
- OpenAI 전사 엔드포인트의 공식 데이터 표에는 학습 사용 No, abuse monitoring/application state retention None으로 기재돼 있다. 이는 해당 엔드포인트의 표기이며 모든 운영 메타데이터·예외까지 무보관이라고 보장하는 표현은 쓰지 않는다. [데이터 안내](https://developers.openai.com/api/docs/guides/your-data)
- CLOVA의 데이터 보관·학습 이용 조건은 이번 API/요금 문서로 확인하지 못했다. 채택 전 별도 확인한다.

## 비교 순서와 합격 기준

1. 기존 합성 WAV 4개를 그대로 사용한다. `artifacts/phase3/asr-diagnostic/`의 주유 3만원·3천원·7만원·주차 3천원. 이 결과는 기존 오프라인 비교와 같은 입력으로 비교하고 사람 발화 결과와 구분한다.
2. 정답 문장이나 금액을 프롬프트로 제공하지 않는다. 처음에는 한국어 지정만 적용한다. API 응답 원문, 현재 파서의 금액/항목, 요청 시작~응답 시간, 오류·호출 횟수를 기록한다. 자동 재시도로 성공 사례만 남기지 않는다.
3. 합성 4건의 금액·항목이 모두 맞으면 사용자 실제 마이크로 실패했던 “주유 3만원”부터 확인한다. 그다음 [검사표](speech-test-checklist-2026-11-09.md)의 정상 12문장을 정해진 순서로 검사한다. 1회차 12/12를 초기 통과 기준으로 삼되 일반 정확도 보장으로 표현하지 않는다. 실패는 숨기지 않고 원문/파서 문제를 나눠 수정 후 전체 회차를 재검사한다.
4. 무음·숫자 누락·복수 지출·시간 초과·네트워크 끊김·취소·P 상태 해제를 검사한다. 녹음/요청 취소 뒤 늦게 도착한 결과가 초안을 덮지 않아야 한다. 어느 결과도 사용자 확인 없이 저장하지 않는다.

음성 인식 성공과 파싱 성공은 별도다. “아~”의 물결표를 금액 범위로 오판하는 현재 안내 문제도 별도로 남아 있다. 금액을 정답에 맞춰 임의 보정하지 않는다.

## 채택 시 최소 연결 구조

`앱의 최대 8초 녹음 → HTTPS 중계 서버 → 선택한 전사 API → 인식 문장 → 기존 금액/항목 파서 → 사용자 확인 → 저장`

- 기존 녹음 권한·오디오 포커스·P 상태 제한·취소 처리는 유지한다. 녹음은 요청 처리 후 폐기하고 서버 로그에 오디오·키를 남기지 않는다. 테스트 원본 보관이 필요하면 별도로 범위와 기간을 정한다.
- API 키는 서버 환경변수에 둔다. 중계 서버에는 인증·요청 크기/길이 제한·시간 제한·사용량 제한이 필요하다. APK에 공용 비밀 키를 넣는 방식은 사용하지 않는다.
- OpenAI 후보 요청: `/v1/audio/transcriptions`, multipart WAV, `model=gpt-transcribe`, `languages[]=ko`. 현재 문서의 복수 언어 필드와 구형 단수 필드를 혼용하지 않는다.
- 개발 중 Mac 중계 서버로 성공해도 제출 완료가 아니다. 심사자가 개발자 Mac 없이 접근 가능한 서버, 최종 APK 연결, README의 인터넷/설정 안내와 실제 설치 검증이 필요하다.
- 인터넷 연결 실패 시 직접 입력을 유지한다. 서버 실패를 금액 0원이나 이전 결과로 처리하지 않는다.

- 합계 8요청, 합성 오디오 9.786875초. 공식 예상 분당 단가로 약 $0.000734이며 실제 청구액/최소 과금 조건을 확인한 수치는 아니다.
