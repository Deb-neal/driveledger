## 11/13 저녁 자동점검 — 제출 음성 경로 재조정

[공식 개발 범위 공지](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000008)에서 차량 마이크 음성을 외부 음성 인식 서비스로 전송할 수 없고 SpeechToText SDK를 사용해야 함을 확인했다. 준비 중 표시와 별개로 개발 문서에 공개된 SDK는 에뮬레이터에서 개발·시험할 수 있다. 공지의 게시/변경 시각은 확인되지 않았으며, 이번 점검에서 새로 확인한 내용이다. 아래 계획보다 이 조정이 우선한다.

- 완료된 실제 결과: 소스 Public 게시, Render 서버 배포, HTTPS 서명 APK 설치·합성 인식·기록 흐름 검사. 외부 경로 동작 성공을 공모전 제출 적합성으로 해석하지 않는다.
- **현 HTTPS APK의 제출·공개 등록 보류.** 다음 개발 작업은 공식 STT SDK 문서/에뮬레이터 지원 확인과 음성 경로 전환이다. 아직 착수·검증하지 않았다. 추가 디자인이나 외부 STT 개선보다 우선한다.
- **11/14:** 공식 STT 전환 가능성을 우선 확인하되, 필수 양식·본인 동의·서명과 서류 우선 접수 회복 목표를 보호한다. 전환이 끝나지 않으면 음성은 미완료/향후 구현으로 정확히 쓰고, 검증된 수동 기록 범위의 산출물 제공을 검토한다.
- **11/15 23:59 전:** 완성된 범위만 영상·APK·README·기획서에 일치시켜 제출한다. 수정 제출은 전체 자료와 서명본을 다시 첨부한다.
- 사용자 직접 작업: 11/14까지 참가정보 최종 확인·본인 동의/서명. 공식 SDK의 실제 발화 시험은 전환/설치가 끝난 후 안내한다. 키 재발급이나 Render 추가 등록은 지금 요청하지 않는다.
- 현재 영상·최종 APK 게시·서명본·발송/접수는 미완료다. Render는 그대로 운영 중이며, 이번 점검으로 정지·삭제·새 배포하지 않는다.

## 2. 1차 제출 범위

핵심 가치: **차 안에서 잊기 전에 한마디로 기록하고, 이번 달 기록된 차량 지출을 확인한다.**

| 반드시 구현할 것 | 범위를 줄이는 방법 |
| --- | --- |
| 실제 마이크 입력으로 지출 한 건 기록 | 한 가지 음성 경로만 채택. 단일 지출·원화·오늘 기록부터 시작 |
| 금액·항목 확인, 취소, 잘못된 기록 수정 | 자유 대화 대신 확인 화면과 짧은 지원 문장. 화면 수정으로도 완료 가능 |
| 앱 재실행 후 기록 보관 | 한 차량·로컬 DB. 로그인·동기화 없음 |
| 월별 총액·항목별 합계·최근 내역 | 홈과 기록 확인/편집 중심의 두 화면. 웹 대시보드·복잡한 차트 없음 |
| 차량특화성 증거 | Vehicle State의 실제 지원 주행거리 조회를 우선. 현재 입력 시점에만 부착하고 미지원이면 미상 처리 |
| 제출 가능한 산출물 | 공식 양식 + 실제 동작 영상 + 소스·설치 가능한 release APK를 목표 |

1차에서 제외: 카드·통행료 자동 수집, 정비 상담·마모 진단, Gleo 호출 통합, 백그라운드 상시 청취, 음성 복수 지출·복잡한 날짜 처리, 사용자 계정, 결제, CSV, 웹 동기화, 대규모 LLM 인프라.

대학 과제에서 설명한 웹 대시보드는 장기 구상이다. 공모전 MVP의 완료 조건에 자동으로 포함하지 않는다. 대학 과제 PPT에는 이름·학번·학교가 있으므로 공모전 작품 소개로 그대로 제출하지 않고 공식 양식에 맞는 별도 자료를 만든다.

### 11/11 작업 순서 — 온라인 실제 발화부터

**후속 결과:** 온라인 입력 “주차 3천원”, “주유 3만원”, “톨비 삼천원”, “주차비 17만원”, “주차 7만원”의 정확한 입력을 사용자가 확인했다. 초기 실제 발화 성공 5건이며 정규 검사·음성 입력의 저장 확인과 구분한다. 공식 DOCX 소개문과 80초 시연 대본 초안을 작성했다. 다음은 온라인 배포 경로 확정, 차량 상태 전환 확인, 서명 release와 최종 서류·영상 준비다.

사용자는 전날 작업 후 잠들었고 온라인 전환 뒤 실제 발화 성공 결과는 아직 알려주지 않았다. 오전 상태 점검에서 Mac relay `/health` 정상, 기존 업스트림 요청 1회(어제 합성 앱 검사), emulator-5554 연결 및 adb reverse를 확인했다. 이 확인만으로 실제 음성 품질을 완료 처리하지 않는다.

1. **사용자 10~20분:** “온라인으로 말하기”에서 주유 3만원 → 주차비 3천원 → 주유 7천원/7만원/17만원을 먼저 확인한다. 성공 여부와 실제 표시 문장·금액·항목을 기록하고 정규 12문장 검사로 이어간다. 정상 한 번과 전체 품질 검증은 구분한다.
2. **개발:** 실제 실패 원인을 보완하고, 심사자가 Mac 없이 사용할 인증/사용량 제한이 있는 HTTPS 서버와 release 연결 경로를 확정한다. 현재 debug 로컬 서버는 제출용이 아니다.
3. **차량 연결 검증:** 실제 SDK P→D→P 입력 제한, 주행거리 단위·기록 첨부, 재시작/실패 흐름. 추가 디자인 변경보다 우선한다.
4. **서류 준비:** 공식 양식의 프로젝트 소개와 영상 대본 초안을 작성한다. 음성 테스트 대기 중에도 진행 가능하다. 오늘 참가 단위·부문·명칭 및 GitHub 공개 여부를 사용자에게 묶어 확인하고, 본인 동의·서명은 대신 확정하지 않는다.
5. **11/12:** 제출용 서명 release 빌드/설치 검사, 소스·README·APK 게시와 링크 접근 확인, 양식·녹화 준비. 게시·발송은 기존 권한 범위를 확인하여 진행한다.
6. **11/13:** 영상·최종 서명·첨부/링크 확인 후 첫 제출 목표. 최종 마감은 11/15 23:59 KST. 오늘 실제 음성/서버 범위가 정리되지 않으면 11/13 가산점 산출물 포함 목표는 다시 조정하고, 필수 서류 접수를 우선 보호한다.

오늘 사용자 직접 작업은 실제 발화 확인과 참가정보/공개 여부 결정이다. 구현·빌드·검증·문서 초안은 Codex가 진행하며 최종 본인 동의·서명과 접수 확인은 별도다. 오늘 점검에서 새 개발·배포·발송은 수행하지 않았다.

### 11/10 작업 범위 — 하루 이월 반영

**온라인 검토 추가:** 사용자가 정확도 우선 온라인 검토를 선택했다. [비교 계획](online-stt-evaluation-2026-11-10.md)에 따라 계정 확인 → 동일 합성 입력 비교 → 실제 발화 → 엔진 통합 순서로 진행한다. 온라인 채택 시 심사 중 접근 가능한 중계 서버와 최종 APK 연결 검증이 추가로 필요하다. 사용자 키 설정 후 합성 4건 API 비교에서 공통 차량 용어 힌트 적용 시 금액+항목 4/4를 확인했다. 이후 debug 앱에 Mac 중계 온라인 경로를 연결·설치해 합성 입력 화면 테스트를 통과했다. 실제 사람 온라인 발화와 제출용 서버가 남아 있다.

**실제 발화 후 갱신:** 사용자 “주유 3만원” → `3rd` 실패. 실제 음성 흐름의 정확도 완료 기준 미충족이다. 입력 길이/포맷·한국어 설정을 확인하고 추가 오프라인 모델을 비교했으나 금액 오류가 남았다. 다음 순서는 음성 인식 경로 개선·동일 음성 비교이며, 11/11 주행거리/통합 작업에 앞서 재판단한다. 연결/안전 동작 자동 검사 통과를 실제 인식 성공으로 대체하지 않는다.

사용자는 11/9 작업을 거의 못했다고 밝혔다. 착수 전 MainActivity와 debug APK는 11/8 상태였다. 11/10 순차 진행 지시에 따라 제품 마이크·P 상태 제한을 연결하고 자동 검사를 진행했다. 이후 실제 사람 발화에서 인식 실패를 확인했다. 텍스트 입력·수정·취소·삭제·월 이동·재실행 보관 검증과 음성 검사표 준비는 그대로 유효하다.

**오늘 최우선 완료 기준:** 실제 마이크 → 인식문 → 금액·항목 확인/수정 → 명시적 저장 → 월 합계 반영. 정상 사례 한 번의 성공과 12문장 전체 정확도는 별도로 보고한다.

- [x] 마이크 시작/끝내기/취소를 제품 화면과 연결하고 기존 오프라인 엔진을 사용한다. 합성 PCM으로 확인·수정·저장 연결 검증.
- [ ] 권한 거부·무음·실패·취소·화면 이탈·오디오 포커스 처리, 확인 전 자동 저장 방지 및 기존 기록 보존을 검증한다. 자동 검사 통과 범위는 검증 기록 참고. 실제 권한 팝업/마이크 실패 경로는 남음.
- [x] P 상태 확인과 주행/미상 상태 입력 제한 연결. 에뮬레이터 SDK P 응답 및 조회 중단 차단 검사. 실제 SDK D 전환 검증은 11/11에 남김.
- [ ] 연결 후 실제 발화 12문장 1회씩 검사하고 금액/항목 원결과·수정값·시간을 기록한다. 특히 7천/7만/17만 원을 우선 확인한다.

오늘 개발·연결·기본 회귀 검사에 약 2.5~3시간, 사용자 실제 발화에 20~30분을 우선 배정한다. 이는 작업 예산이며 정확도 개선과 모든 예외 검증까지 3~4시간 내 완료한다는 보장은 아니다. 오늘 끝나지 않은 검증은 미완료로 남긴다.

**후순위:** 추가 디자인 변경·새 기능·음성 엔진 다중 비교·휴대폰 추가 대응을 당장 넓히지 않는다. 주행거리 단위 확인/저장 연결 및 차량 상태 변화·실패 경로의 나머지 검사는 11/11로 조정한다. 냉간 화면 밀림 재검증과 CarIME 보완은 삭제하지 않고 안정화 목록에 유지한다.

**제출 일정 보호:** 11/11에는 핵심 통합 검사와 공식 양식/영상 대본 초안을 준비하고, 확인된 범위로 release 작업에 넘어간다. 11/12는 서명 release APK 설치, README/저장소 게시 준비, 서류·녹화 준비에 집중한다. 참가 단위·부문·공개 여부는 11/11까지 사용자 결정이 필요한 항목으로 묶는다. 서명·동의는 본인 확인 전 확정하지 않는다. 11/13 첫 제출은 조건부 목표, 최종 11/15 23:59는 유지한다.

오늘도 실제 음성 흐름이 나오지 않으면 밤 점검에서 작동하는 범위/미구현을 분리한 영상·소개서와 필수 양식 우선 제출 경로를 재판단한다. 선택 산출물 때문에 필수 접수를 놓치지 않는다. 이 일정 점검만으로 개발·게시·발송을 실행한 것은 아니다.

### 11/9 작업 범위 — Phase 3 첫날 계획

목표는 **제품 화면에서 실제 목소리로 지출 한 건을 입력하고, 사람이 확인한 뒤 저장하는 흐름**이다. 시작 점검 시 MainActivity에는 마이크 연결이 없고 ProbeActivity에 별도 진단용 음성 구현이 있다. 기반 코드를 제품에 연결할 작업이며 아직 착수·완료로 표시하지 않는다.

| 우선순위 | 작업 | 예상 작업 예산 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 앱 마이크 시작·끝내기·취소와 기존 오프라인 엔진 연결 | 60~90분 | 실제 인식문을 금액·항목 확인란으로 전달. 명시적 확인 전 자동 저장 없음 |
| 2 | 권한·무음·실패·화면 이탈·오디오 포커스 처리 | 40~60분 | 복구 경로 제공, 취소/이탈 시 마이크 해제, 늦은 결과가 초안을 덮어쓰지 않음 |

| 4 | 연결 후 실제 발화 12문장 1회씩 및 핵심 저장/취소 검사 | 20~30분 | 검사표에 첫 인식 결과·수정값·시간 기록. 발화 검사는 사용자의 참여가 있어야 완료 |

위 시간은 합계 150~220분의 작업 예산이며 완료 보장이 아니다. 환경 문제·금액 오류 해결에 추가 시간이 들면 11/10과 조정한다. 금액 확인·취소·마이크 해제·차량 상태 제한을 일정 때문에 생략하지 않는다.

- [x] 일정·현재 제품/진단 코드·발화 검사표 대조.
- [ ] 제품 마이크 연결 및 확인 후 저장 흐름.
- [ ] 권한·취소·마이크 해제·차량 상태 제한 검증.

### 11/7 작업 범위 — 완료 기록

오늘의 목표였던 **지출 한 건을 확인·수정해 저장하고, 앱 재실행 후 내역과 월 합계에서 확인하는 것**을 검증했다. 아래는 착수 전 작업 예산이며 실측 소요 시간이 아니다.

| 순서 | 작업 | 예상 시간 |
| --- | --- | --- |
| 1 | 홈·확인 화면 구성: 월 합계, 최근 내역, 기록 버튼, 금액·항목 입력 | 30~40분 |
| 2 | 제한된 지출 문장에서 금액·항목 추출, 저장 전 수정·취소 | 50~60분 |
| 3 | 로컬 DB 저장, 최근 내역·이번 달 합계 연결 | 60~80분 |
| 4 | 취소·중복 저장·합계·재실행 후 보관 검증 | 40~50분 |

- 우선 예시: “오늘 주차비 삼천 원” → 주차비 / 3,000원 확인 → 저장 → 월 합계 반영.
- 음성 엔진과 분리해 텍스트로도 기록 흐름을 검증한다. 인식이 불명확한 금액·항목은 추측해 저장하지 않는다.
- 저장된 내역 수정·삭제, 항목별 집계, 월 경계 검증도 11/7에 함께 마쳤다. 11/8은 직접 사용과 발견한 오류 보완에 쓸 수 있다.
- 실제 사용자 발화 정확도, 차량 상태와 입력 제한 통합은 Phase 3에서 검증한다. 화면 장식보다 금액·보관 정확성을 우선한다.

## 4. Phase 1에서 결정할 기술 경로

### 개발 환경

- 공식 최소 조건: minSdk 28 이상, Gradle 8.0 이상, Java/Kotlin 중 Kotlin.
- 기존 확인 기준: Pleos Emulator 2.1.0 / API 34, Vehicle SDK 2.3.2, STT/TTS 3.3.1. 실제 설치 시 최신 문서·제공 패키지와 다시 대조한다.
- minSdk·compileSdk·targetSdk·AGP·Gradle·JDK를 혼동하지 않는다. 로컬 JDK 21에 맞는 Gradle/AGP 조합을 검증하거나 Android Studio의 호환 JDK를 사용한다.
- 읽기 전용 차량 데이터만 사용한다. 상태 미확인을 주차나 정상 값으로 간주하지 않는다.

### SDK 사용 가능 상태 — 이번에 확인한 중요한 제약

**11/5 실행 결과:** Vehicle 데이터 조회 성공. Android 기본 음성 서비스는 있지만 결과 응답을 받지 못했다. 개발용 대체 경로로 Whisper tiny int8의 오프라인 실행을 검증했다. 서버형 ASR을 추가하지 않았으며, 아래 절차의 위험 판단과 실제 발화 검증은 계속 적용한다.

[공식 프로젝트/SDK 안내](https://document.pleos.ai/docs/pleos-only/create-my-project)는 **Vehicle State와 NaviHelper를 신청 없이 사용 가능**, **STT·TTS·FusedLocation·Vehicle Control을 준비 중**으로 설명한다. 사용자의 실제 프로젝트 화면에서도 네 항목의 Coming Soon을 확인했다. 과거 계획의 “STT/TTS를 바로 붙인다”는 가정을 유지하지 않는다.

1. 프로젝트의 실제 SDK 상태와 에뮬레이터에서 쓸 수 있는 음성 경로를 확인한다.
2. Pleos STT가 사용 가능하면 실제 마이크로 검증하고 채택한다.
3. 사용할 수 없으면 에뮬레이터에 제공되는 인식 서비스 등 대체 경로를 확인한다. Android API가 있다는 이유로 해당 차량에서 실행 가능하다고 가정하지 않는다.
4. 외부 음성 API가 필요한 경우 하나의 제공자만 선택하고 백엔드·네트워크·비용·키 관리까지 함께 산정한다. FreeLLMAPI나 VoiceStudio 전체 설치를 우회 해결책으로 자동 채택하지 않는다.
5. 11/6 말까지 경로가 정해지지 않으면 11/7 초에 시간 상한을 두고 대안을 검증한 뒤 제출 산출물 수준을 재판단한다. 음성 처리 없이 텍스트만 동작하면 “음성 구현 완료”로 표시하지 않는다.

지출 문장 해석은 제한된 규칙으로 시작한다. LLM은 자유 표현에서 실제로 이점이 확인되고 구현 시간이 허용될 때만 추가한다. 금액 검증·합계·저장은 결정적 코드로 처리한다. 별도 제공자의 비밀 API 키를 APK에 포함하지 않는다.

## 6. 검증과 사용자 테스트

- 돈: 원 단위 정수, 빈/불명확한 금액, 수정 후 합계, 중복 저장, 취소, 월 경계, 삭제와 재실행 보관을 검증한다.
- 차량: 주행거리 출처·조회 시각·미지원과 정상 0을 구분한다. 입력일이 다른 과거 기록에 현재 주행거리를 붙이지 않는다.
- 음성: 권한 거부, 인식 실패, 네트워크 실패, 중단·재시작, 앱 종료 후 마이크 해제를 확인한다.
- UI: 안전하게 주차한 상태에서 입력·확인·편집하고 주행 중 규제 정책을 준수한다. Impeccable은 실제 두 화면의 가독성·오류·빈 상태·조작 흐름 검토에 사용한다.
- 사용자 테스트는 가능한 운전자 3~5명에게 같은 지출 몇 건을 기록하도록 하여 시작부터 저장까지 시간·조작 수·정확도·수정 횟수를 비교한다. 하루 테스트만 가능하면 그 범위를 정직하게 보고한다.
- 11/9 이후 테스트를 시작하면 1차 제출 전 D7·D30을 관찰했다고 주장할 수 없다. 초기 사용성 결과를 제출하고 장기 재사용률은 후속 검증 계획으로 둔다.
- MAU·유지율·절약 효과를 임의로 실적으로 만들지 않는다. 추정이면 모집·활성화 가정과 표본 부족을 표시한다.

## 7. 외부 도구의 적용 시점

- Ponytail: 이번 범위 축소와 이후 개발에 적용. 표준/플랫폼 기능과 작은 구현을 우선하되 데이터 정확성·오류 처리를 유지한다.
