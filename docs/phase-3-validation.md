## 11/10 실제 사용자 시험 — 입력 경로 점검 중

사용자가 MacBook에서 시험 후 “말소리를 확인하지 못했어요” 안내를 보고했다. 발화 문장/소요 시간/입력 음량은 미확인으로 성공 처리하지 않는다. 코드상 저신호·짧은 입력 또는 ASR 빈 결과가 같은 안내를 사용하므로 이 메시지만으로 원인을 확정할 수 없다. 현재 앱 RECORD_AUDIO 허용, AVD hw.audioInput=yes 및 -no-audio 없이 실행 중인 것은 확인했다. 호스트 마이크 전달 토글과 macOS 권한은 미확인이다. 네이티브 에뮬레이터 설정 창을 자동화 도구에서 찾지 못해 사용자가 Extended Controls → Microphone에서 확인하도록 안내한다. [Android 공식 호스트 마이크 안내](https://developer.android.com/studio/run/emulator-extended-controls).

사용자 캡처에는 외부 도구막대가 보이지 않았다. 설치된 에뮬레이터 콘솔의 `help avd`에서 `hostmicon` 지원을 확인하고 `adb -s emulator-5554 emu avd hostmicon`을 실행해 OK 응답을 받았다. 호스트 입력 활성화 명령 수락만 확인했으며 macOS 권한·실제 사람 음성 수신/인식 성공은 재시험 대기다. 앱 녹음은 자동으로 시작하지 않았다.

호스트 입력 활성화 후 사용자 캡처에 인식문 `아~ mic test 21919`가 표시됐다. 사용자가 보고한 실제 발화는 “아아 마이크 테스트 주유 3000천원 입력해줘”다. 주유/금액 구간이 보존되지 않은 실패 사례로 기록한다. 금액 표기 `3000천원`의 실제 발음/의도, 전체 발화가 8초 수음 구간 안에 들어왔는지, 지연 시간은 미확인이다. 원본 녹음이 없어 수음 잘림과 ASR 오류를 구분할 수 없다. 기존 tiny/base 합성 비교에서도 금액 오류가 있었으므로 연결 성공을 실사용 정확도 통과로 계산하지 않는다. 화면의 범위·환불·계산식 안내는 인식문 `~` 기호에 파서가 반응한 것으로, 이 사례에 부적절한 안내이며 별도 보완 대상이다.
