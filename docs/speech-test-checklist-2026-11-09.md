# Phase 3 실제 발화·기록 검사표

작성일: 2026-11-08 KST · 갱신: 11/11 온라인 실제 발화 2건 성공

**11/10 사용자 자유 발화 시험에서 “주유 3만원” → `3rd` 인식 실패를 확인했다. 아래 정해진 검사표의 전체 회차는 아직 미실행이다.** 11/10 제품 화면의 앱 마이크·확인 화면·P 상태 입력 제한을 연결했다. 합성 PCM 및 가짜 입력 소스를 사용한 자동 검사는 [Phase 3 검증 기록](phase-3-validation.md)에 별도 기록하며 이 검사표의 실제 사람 결과로 대체하지 않는다.


## 11/11 실제 사용자 온라인 인식 성공 — 자유 발화 2건

사용자가 온라인 연결 확인 후 “주차 3천원”, “주유 3만원”을 각각 테스트했고 두 건 모두 정확하게 입력됐다고 보고했다. 사용자 보고 기준으로 주차 3,000원·주유 30,000원 인식 성공을 기록한다. 이는 실제 사람 발화이며 이전 합성 음성 비교와 구분한다.

- 직전 확인 환경: `0.3.0-phase3-online-test`, Pleos 에뮬레이터, Mac 마이크/중계 서버, OpenAI 전사 및 차량 지출 용어 힌트.
- 정확한 전사 원문·스크린샷·지연 시간·반복 횟수는 제공되지 않았다. 두 사례의 성공을 전체 정확도 100%로 표현하지 않는다.
- 저장 버튼·DB/월 합계 반영은 이번 보고에 포함되지 않아 미확인이다. 기존 저장 검증과 구분한다.
- 정규 12문장과 표현이 다르므로 해당 표의 완료 칸을 대신 채우지 않는다. 다음은 오늘 주유 칠천 원 / 칠만 원 / 십칠만 원의 금액 구별을 확인한다.

## 1. 실행 준비

- 제품 화면에 실제 마이크 → 인식 → 금액/항목 확인 경로를 연결한 뒤 시작한다. Pleos 키보드 마이크와 앱 마이크를 혼동하지 않는다.
- 안전하게 주차한 상태에서 검사한다. 주행 상태 전환은 에뮬레이터로 검증하고 실제 주행 중 조작하지 않는다.
- 빌드 식별자/APK SHA-256, 앱 버전, 기기·OS, 엔진/모델, 마이크 입력 경로, 차량 상태 출처, 날짜를 기록한다. 에뮬레이터 사용 시 호스트 마이크 전달이 켜졌는지 확인한다.
- 기존 기록의 건수와 해당 월 합계를 기준값으로 남긴다. 가능하면 분리된 테스트 기기/사용자를 사용한다. 전체 데이터 초기화는 하지 않으며 정리할 때 검사에서 만든 기록만 구분한다.
- 화자는 P01 같은 식별자로 기록한다. 기본 검사는 조용한 정차 환경·평소 말투로 시작한다. 합성 음성과 사람 발화를 섞지 않고, 음성 원본 파일을 기본 저장하지 않는다.
- 결과 기록용 [CSV](speech-test-results-template.csv)를 별도 복사해 사용한다. 실행 전 빈 칸을 실패/성공으로 채우지 않는다.

## 3. 애매한 입력·미지원 표현 — 자동 확정 방지

표의 금액/항목은 **인식된 문자열이 표의 문장과 동일할 때의 현재 파서 기준**이다. ASR이 내용을 바꾸면 실제 인식문과 발화 의도를 함께 비교한다. 예를 들어 E08이 “7만 원”으로 인식되면 파서가 70,000원을 제시할 수 있지만, 이것을 “일곱만” 원문 파싱 지원이라고 기록하지 않는다. 어떤 경우에도 사용자 확인 전에 자동 저장하지 않는다.

## 5. 한 회차 진행 순서

1. 시작 전 월 건수·합계와 차량 상태를 적는다.
2. 마이크를 시작하고 지정 문장을 한 번 말한다. 실제로 말한 문장과 엔진 인식문을 각각 기록한다.
3. 처음 제시된 금액·항목을 **수정 전에** 기록한다. 실패/무응답도 기록하며 자동 저장이 없는지 확인한다.
4. 필요한 경우 직접 수정하고 수정 횟수를 기록한다. 정상 사례는 저장, 미지원/취소 사례는 해당 안내 또는 취소 흐름을 검사한다.
5. 저장 후 건수는 +1, 합계는 최종 확인 금액만큼 증가했는지 비교한다. 취소/차단은 둘 다 변화 없어야 한다.
6. 음성 종료→결과 표시 시간과 마이크 시작→저장 완료 시간을 각각 기록한다. 취소한 회차의 저장 완료 시간은 해당 없음으로 둔다.
7. 결과를 통과/실패/차단/미검증으로 구분한다. 미구현·설정 실패는 차단이며 통과가 아니다. “금액 인식 실패, 수정 후 저장 성공”처럼 인식 품질과 저장 정확성을 별도로 남긴다.

## 6. 결과 판단 — 내부 기준이며 공모전 공식 배점 아님

- 금액 정확도: V01~V12 실행 전체 중 첫 제시 금액이 발화 의도와 같은 횟수 / 정상 발화 실행 수. 무응답·인식 실패를 분모에서 빼지 않는다.
- 항목 정확도와 금액+항목 동시 정확도도 같은 분모로 각각 계산한다. E/S는 정상 발화 정확도 분모에 섞지 않는다.
- 저장 정확성: 모든 저장은 사용자가 마지막에 확인한 금액·항목과 일치하고, 중복 저장은 0건이어야 한다. 취소·차단 후 DB 변화가 있으면 실패다.
- 권한 거부/화면 이탈/취소/차량 상태 차단에서 마이크가 남거나 자동 저장이 발생하면 해결 전 완료 처리하지 않는다.
- 시간은 실제 측정값과 시도 수를 함께 보고한다. 성공 회차만 측정했다면 그 사실을 밝힌다. 작은 표본으로 보편적 성능·사용자 유지율을 주장하지 않는다.
- 음성 정확도 합격 수치는 아직 정하지 않았다. 측정 후 실제 오류를 보고 지원 문장 축소·엔진 개선 여부를 결정한다. 금액 오류가 있었다는 사실을 숨기지 않으며 확인/수정 단계를 유지한다.
- 현재 결과: 실행 0회, 정확도/지연/성공률 미측정. 시연 영상에서 검사표 준비를 실제 음성 검증 완료로 표현하지 않는다.
